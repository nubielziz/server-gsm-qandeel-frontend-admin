# 036 Fewer inputs in Settings, Shop content, System health and Notifications

**Context.** On 2026-11-27 the owner asked to reduce how much staff type in the console and agreed a numbered list. Three kinds of change: **remove** (the console
sends the fixed or computed value, or leaves the key out where the server makes it), **hide** (the input moves into the kit's `<MoreOptions>` fold, keeps its
default and is still sent as before) and **menu** (a typed text becomes a choice; a stored value the menu does not know stays chosen). The rule of the fold is
decision 035: one fold per form, after the visible inputs, labelled "More options"; it starts open (`defaultOpen`) when a record being edited holds a value that
is not the default of a hidden input, and is forced open (`forceOpen`) while a hidden input has an error (a client check or a server message). The wire format does
not change for a form left at its defaults, except where an item says the key is left out (and the backend's decision 077 makes it).

**Decision.** One line per item (the owner's numbers):

| # | where | what replaced the input |
|---|---|---|
| 14 | Shop page of a service: Slug | No input. The address is shown as a plain value ("Address (slug)") and is never sent in an update (`slug` left the form values and `changedBody`). The console has no form that creates a shop page; `CreateListingBody.slug` was already optional. The publish preview's own "Address (slug)" is untouched. |
| 15, 16, 17, 39 | Shop page: Search title, Search description, Position, Delivery note | One "More options" fold at the end of the form (`ListingMoreFields`). Defaults: empty texts, position 0 (the server's default), so a shop page with a delivery note, a position other than 0 or a search text opens the fold. The hint of the delivery note says "Empty: the shop shows the service's delivery time." |
| 18 | Content page dialog: Slug | A new page has no Slug input and no `slug` key is sent (the server makes it from the title); an edit keeps the Slug input. A server message about the address of a new page falls to the dialog's error slot (the field is not in the form). |
| 19, 20 | Content page: Search title, Search description | In the fold; open on an edit of a page that has either. |
| 21 | Legal document, new version: Version | Not typed: the next number of the chosen document, shown read-only and sent as before. Started from a document it is `suggestNextVersion(from.version)` (as today); from the "New version…" button it is the number after the newest version of the document picked in the menu (`nextVersionFor`, `1.0` for a document with none), recomputed when the menu changes. The server's message about the number shows under the value. |
| 22 | Help article: Topic | A menu of the topics the articles already use (one unfiltered read of the list, up to 200, sorted) plus "New topic…" which shows the box; the box alone while no article uses a topic yet; a stored topic the list does not know stays chosen. The value sent is the topic text. |
| 27, 28, 29 | Add currency: Code, Name, Decimals | Code is a menu of the ISO 4217 codes the browser knows (`Intl.supportedValuesOf('currency')`, a built-in list of 43 when it is missing), "CODE - Name", without the codes already added. Name (`Intl.DisplayNames`) and Decimals (`Intl.NumberFormat` fraction digits, kept in 0 to 4) are not asked and are sent as before. When editing, Name and Decimals are in the fold (the form never showed them on an edit before; a PATCH may send them, the server accepts both); the fold starts open when they differ from what the code gives. A server message about decimals on an add falls to the dialog. |
| 30 | Currency: Rate | **Not hidden** (a deviation from the owner's list, decided by the lead): production runs with manual exchange rates, where "Refresh rates" fetches nothing, so the rate must be typed. The hint now says so. |
| 31 | Payment method: Code | No input when a method is added (custom or ready-made): no `code` key is sent and the server makes it (backend decision 077: from the name, or from the preset's key, lower-case letters, digits and underscores, with `_2`, `_3` when taken). `CreateGatewayBody.code` is optional; the mock makes the code the same way (`madeCode`). On an edit the code is shown read-only as before. `freeCode` is removed (nothing else used it). The webhook address (it contains the code) is shown once the method is saved. |
| 38 | Payment method: Driver | A custom method's driver is a menu: Bank transfer (`bank`), Card (`card`), Crypto (`crypto`), Wise (`wise`); a new method starts on `bank`; a stored driver the menu does not know stays chosen as it is. A ready-made method keeps its fixed read-only driver. |
| 32 | Tax rate: Country | A menu of the 249 assigned ISO 3166-1 codes, named by `Intl.DisplayNames`, "Name (CODE)", sorted by name, built in `settings/lib/countries.ts` (the codes are listed there: the browser also names reserved and retired codes such as EU, UN, SU that are not countries). The two-letter code is sent. A saved rate shows its country as a plain value. `countryName` now names any ISO country, so the table and the toasts say "Japan", not "JP". |
| 33 | Tax rate: Region, Until, Reported through, Applies to, Label | In the fold (open on an edit that holds any of them). Visible: Country, Rate, Kind of tax, Rate applies from, which starts on today (the UTC day, as the dates are kept) for a new rate. |
| 34 | Notification template: Event | A menu of the events the system sends for the chosen audience, labelled with `eventLabel`; a stored event the list does not know stays chosen; changing the audience starts the choice again; a saved template shows its event as a disabled menu. `TEMPLATE_EVENTS` in `lib/templates.ts` copies the backend's registry (platform `notification-events.ts` `BUILT_IN_EVENTS`, identity `identity-mail-events.ts` `IDENTITY_MAIL_EVENTS`; the broadcast events have no template and are left out). |
| 35 | Alert rule: Key | No Key input when a rule is added and no `key` is sent (backend decision 077: made from the name, `_2`, `_3` when taken). `CreateAlertRuleBody.key` is optional; the mock makes it the same way (`madeKey`). On an edit the key is a plain value and is never sent (it left `RuleValues` and `toUpdateBody`). A server message about the key falls to the dialog. |
| 36 | Maintenance: message and expected end | The message **stays visible and editable** and starts filled with "We are doing scheduled maintenance. Please try again in a little while." when none is stored (a small deviation from "hide": a message customers read should be seen before it is sent). The expected end is in the fold (open when one is set). |
| 37 | Notification campaign: the three links | Each link is a menu: "No link", the known pages of that audience, "Another page…" which shows the text box (the same path check as before); a stored link the menu does not know shows as "Another page…" with its text. Staff: the console's 14 pages (a copy of `src/app/resources.ts`, not imported because the app imports the features). Merchants and retail accounts: the shop's account pages, the same list for both (Account home, Orders, Wallet, Invoices, Support, Notifications, Settings), checked against the shop's `app/en/account` folder. The merchant placeholder `/merchant/orders` was out of date (the server wants `/account/...`, its decision 064) and is now `/account/orders`. |

**Consequences.**
- A small read-only "label and plain value" component exists in three features (`ReadField` in storefront, settings and system-health alerts), because the kit has none and
  a feature may not import another's.
- Every form's tests prove the request body of a form left at its defaults, and that the fold starts open, stays closed, and cannot be closed over an error.
- The mocks keep the wire shape: a create body without `code` (gateways) or `key` (alert rules) is answered with the made value; a body with one is still checked.
