# 013 Lint and format

**Decision.** ESLint 10 flat config (ESLint 9 reached end of support during setup): `@eslint/js` recommended, `typescript-eslint` recommended (type-aware rules not enabled, to keep lint fast), `eslint-plugin-react-hooks` limited to `rules-of-hooks` and `exhaustive-deps` (its React Compiler rules are left off until the code is compiler-ready), `eslint-plugin-react-refresh` (`configs.vite()`), `eslint-config-prettier` last. `--max-warnings 0`, so `exhaustive-deps` warnings fail lint. Guard rails: no `axios`/`ky`/`node-fetch`/`@refinedev/simple-rest`; no `fetch`, `window.fetch` or `globalThis.fetch` outside `src/lib/api`, `src/mocks` and tests; no deep imports into another feature (`@/features/*/*`), except `app/routes.tsx` loading `@/features/*/pages`; no `src/mocks` or `msw` imports (alias or relative) outside `src/main.tsx`, `src/mocks` and tests; `components/` and `lib/` never import `features/` or `app/`. Prettier 3 (printWidth 110, single quotes, trailing commas) formats code; `npm run lint` = `eslint .` + `prettier --check .`; `npm run format` fixes. Ignored: `reference/`, `dist/`, `coverage/`, docs, generated files.

**Consequences.** The fetch-only and feature-boundary rules are enforced by the linter, not by memory.
