## Page and permissions
- Page permission (manifest, any-of): `['storefront:read', 'legal:read', 'catalog:read']`; actions check storefront:* (read/create/update per MISMATCHES M7), storefront:publish, legal:* and legal:publish, catalog:* for the TAC catalogue.
- Tabs (URL `tab`): **Services on sale** (listings: the demo's table, list/unlist (`sf-list`) and retail price edit (`sf-price`) via PATCH; selling below the floor is refused by the server: show its message; "Add listing" via POST with a service picker (private read-only lookup on `GET /admin/services` without `@route`)), **Landing pages** (content pages of landing kinds: carrier, phone model, free tool, brand, country (`sf-kind` filter); row menu edit / publish / hide; **Generate drafts…** via `POST /admin/content-pages/generate` (brand × model × network inputs; the result lists the drafts created for review)), **Content and legal** (content pages + legal documents: versions per type (terms, privacy, refund) with "New version…" (POST) and **Publish** (`POST /admin/legal-documents/:id/publish`, legal:publish, confirm: "it appears in later consents"); page publish/hide toggle `pg-toggle` via `POST /admin/content-pages/:id/publish` with assumed body `{ published: boolean }`), **Help centre** (articles list, create/edit dialog with a Markdown textarea, publish toggle `help-toggle` via PATCH), new **TAC catalogue** (catalog:read: prefix → brand and model; search, create, edit).
- **Live preview** tab: replaced by a link "Open the storefront" to `import.meta.env.VITE_STOREFRONT_URL` (new tab) when the variable is set (MISMATCHES M4); no preview flow.
- Editors: page and article bodies are plain text/Markdown in a textarea (no rich-text dependency); show the server's validation errors under the fields; slugs as the server returns them.
